# M2 schema mapping

M3 adds a fourth migration for app_account_states, app_password_reset_tokens, app_notification_events and app_notification_deliveries, using signed INT references to Users and restrictive history FKs. M4 adds a fifth migration for app_private_uploads, which stores metadata for new private profile/document copies without changing imported BLOBs or app_private_files provenance. M5 adds a sixth migration for app_job_transitions, an append-only state history with no foreign key to Jobs so deletion history remains readable. The target has 21 tables after M5. Existing users and first imports receive unverified identity rows without mail; original source columns/rows remain intact. See [M3 report](../../../docs/m3-identity-permissions.md), [M4 report](../../../docs/m4-contractor-workflows.md), and [M5 report](../../../docs/m5-jobs-notes-media.md). The sections below describe the preserved M2 schema.

Three M2 migrations now map all 11 exported tables from reviewed schema-only definitions in database/schema/legacy.php. Domain tables preserve the 77 original columns, signed INT/custom keys, defaults, nullability, indexes and next AUTO_INCREMENT values. Engine changes to InnoDB and text tables to utf8mb4_unicode_ci are documented and byte-verified in [M2 report](../../../docs/m2-data-migration.md).

The second migration creates app_import_runs, app_import_rows and app_private_files for immutable source digests, row reconciliation and reversible private BLOB mappings. The third adds 12 restrictive domain foreign keys and Files.unique_file_id uniqueness. ActivityLogs.user_id has no foreign key: 15 exported orphan references are preserved. No cascades silently remove history; later deletion workflows require explicit reference handling and the reviewed retention rules.

Default Laravel users, jobs, cache and session migrations were removed before execution. MariaDB on this Windows host has `lower_case_table_names=1`; users/jobs would collide with legacy Users/Jobs. Future framework tables must use the app_ prefix, including app_queue_jobs, app_queue_failed_jobs, app_queue_batches, app_sessions and cache tables. The migration repository is app_migrations.

The populated nestcrafters_local contains 412 reference rows; native staging is nestcrafters_m2_legacy and its dedicated account is now SELECT-only. Run php artisan migrate then nestcrafters:import-legacy with an absolute SQL path only against the documented isolated local setup. The importer refuses production/nonlocal/unlisted connections and detects edited baselines on rerun. No factories/seeds with private reference data exist. File sessions/cache, synchronous queues and captured local mail remain.

Rollback/rebuild was tested on disposable nestcrafters_m2_test only. Rolling back the populated target removes tables and does not remove private file copies. Preserve an independent database/file backup and do not use migrate:fresh or rollback as a routine refresh of imported data. Actual release rollback/transfer needs a separately authorized plan.
